# Offline strategy wiring checkpoint

**Status:** host-only, synthetic/injected strategic provider. Phase A–D contracts remain approved offline; this extension does not deploy to BEEP, call a hosted model, read a live producer, or enable semantic motor dispatch. Hardware motion remains gated.

- `beep_agent/checkpoint.py` writes `AgentSession` v2 and `GoalCoordinator` v2 as **one** validated JSON document. It snapshots under coordinator→strategy locks, writes/fsyncs a temporary file, atomically replaces the target, then fsyncs the directory. A stable advisory lock plus generation fencing prevents two cooperating stale writers from overwriting one another. Restore validates the exact boot/session and bound lease; a corrupt or mismatched pair fails closed. Pass `expected_robot_id` and `expected_boot_id` when loading against a real controller readback. The append-only `EventJournal` is a **different file, not part of this atomic transaction**; this does not claim journal/checkpoint exactly-once durability or hardware ownership after a restart.
- `beep_agent/model_session.py` accepts one injected, long-lived inference callable and validated journal-backed `ModelWindow`s. At most one inference runs; queued windows coalesce to newest, and a response to an older window is discarded. The model sees a bounded `StrategicOwner.build_context()` plus evidence metadata, **not raw media/event payloads**. Journal identity/owner/map/timestamp and event contents are checked before a window is offered and again before a proposal is admitted. A changed world sequence or current map, missing/rewritten journal record, malformed response, expired proposal or competing goal revision cannot revise the goal. Only `StrategicOwner.submit()` can admit a strict typed `GoalProposal` and it confers no motor authority. Provider failures are local outcomes, not a reason to restart the locomotion clock.
- The provider is **not an actual GLADIS/Hermes model connection**; the injected callback tests only the adapter boundary. The adapter object is reused across calls, but its in-flight queue and high-water window number are process-local and **not persisted** in the combined checkpoint. On restart, callers must restore the exact checkpoint and reconstruct/revalidate fresh journal evidence before offering a new window; never replay an old model output.

Run `python -m unittest discover -s tests -p test_offline_strategy_adapter.py -v` and `python -m unittest discover -s tests -q`. Live producers, provider authorization/consent, model latency, atomic journal+checkpoint reconciliation, onboard owner readback, and Phase E commissioning remain open.
