# Phase D offline checkpoint: audio capture, barge-in and social handoff

**Status:** Slice 1 offline contracts were externally approved after `d57fb1f`. Slice 2 below is an **unreviewed offline extension**. No live ALSA capture or speaker-mixer integration; no commissioned SpeexDSP/WebRTC AEC, real transcription, actual TTS interruption, stop-word recognition, or hardware benchmark. Hardware motion remains gated.

- `beep_audio/capture.py`: exact 20 ms, 16 kHz signed-16-bit mono frames, boot/session identity, increasing sequence and robot-clock stamps, and a bounded ring. `PcmCapture` accepts an injected byte source and labels its clock `ingest_approximate`, **not** measured exposure. A short read fails instead of padding with invented audio. It does not open BEEP's microphone.
- `beep_audio/vad.py`: configurable sample-RMS hysteresis for `onset`/`end`. Energy is not speech recognition. Gait noise, quiet speech, and thresholds need measurement; no VAD event commands a stop or gait change.
- `beep_audio/echo.py`: confirmed-render-reference contract, strict matching boot/session, bounded render history, fixed-delay/tolerance alignment, and fixed-gain **synthetic linear** subtraction. Offline playback-only fixtures leave no onset, while injected synthetic near-end audio raises an advisory `cut_tts` decision after two frames and holds it while playback and VAD speech remain active. A playback-on/off transition clears partial counters but preserves an open utterance through TTS cut so its `vad_end` can arrive. Sequence *and* 15–25 ms inter-frame robot-clock cadence guard consecutive VAD evidence; an active utterance interrupted by a capture gap or lost echo reference emits `vad_aborted` instead of silently vanishing. Missing/unconfirmed render reference, approximate capture stamp, timing mismatch or drift yields `short_tts_chunks=True` and no asserted barge-in. The gate keeps VAD active during TTS. This is a test harness, **not a real room AEC**: changing acoustic paths, independent ALSA clocks, nonlinear 3× analog playback, gait, double-talk, and clipping are not solved.
- Decisions have `motor_authority=False`; `cut_tts` is a request for a future mixer, not executed playback control. `vad_aborted` is a **local utterance terminal signal** for the future transcription/mixer consumer, not a valid v1 `TacticalEvent.source`; map or extend it explicitly during integration rather than submitting it unmodified. Only supported `vad_onset`/`vad_end` events may enter the existing exact-identity `TacticalGate` after validation. A separate verified local/physical stop path is required; an RMS onset cannot authorize it.

## Slice 2: offline adaptive reference and social handoff (review pending)

- `beep_audio/adaptive.py` accepts only exact session/boot and confirmed render frames with measured robot-clock timestamps. It keeps at most 128 render and 64 capture frames, requires 12 frames from each stream to warm up before asserting an aligned residual (otherwise short TTS chunks), estimates independent frame periods by bounded timestamp regression (not buffer-fill ratio), maps capture sample times onto the render PCM with linear interpolation, and subtracts a **synthetic fixed echo gain**. Injected ±180 ppm render drift, independent capture/render drift, bounded callback jitter, and added near-end audio are covered by deterministic PCM tests. Drift beyond `max_ppm`, frame loss, missing reference, approximate capture timestamps, a large render timestamp jump or exhausted history fails closed; route reset explicitly reacquires. This is **not acoustic echo cancellation**: unknown gain/room impulse response, nonlinear speaker, real double-talk, actual sample-clock measurements and CPU/latency remain unbenchmarked. The 15–25 ms capture cadence limit remains; bounded jitter is not permission to ignore a real ALSA overrun.
- `BargeInGate` accepts the `EchoProcessor` interface and carries a near-end PCM frame **only** when the mic is unaccompanied by TTS or the echo processor supplied a residual. `beep_audio/social.py` collects at most 500 consented, measured, exact-owner frames; missing residual, `vad_aborted`, consent withdrawal, owner change, cadence loss and duration overrun terminate the utterance without producing an ASR request. A synthetic end-to-end fake-mixer replay cuts TTS, preserves the utterance and emits a single `TranscriptionRequest`. This request is a **local value**, not an upload, and it does not authorize speaking, steering or stopping.
- A bounded metadata-only receipt set admits a `TranscriptResult` once under exact session/boot/mission/lease, continuing consent and a 10-second robot-clock limit, yielding advisory `SocialTranscript` text. A literal “Stop please” is still only text; a separate deterministic stop authority remains necessary. Pending receipts retain **no PCM**, although the returned request's consumer must enforce its own retention/privacy policy. Neither this module nor the tests call a cloud ASR, modify GLADIS strategy or actuate a mixer.

**Next integration gates:** a real 16 kHz USB-mic producer with measured capture timestamps; actually rendered analog speaker PCM/timestamps (not merely queued TTS); real AEC backend and measured delay/clock drift under positive/negative ppm, playback jitter, gait and double-talk; measured latency/CPU/echo return loss/near-end speech intelligibility; interruptible TTS mixer, explicit ASR consumer/retention, social strategy admission, and independent reliable stop control. Until then, use short TTS chunks and do not advertise hardware barge-in.
