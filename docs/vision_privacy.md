**Scope:** host-only source and offline tests. No Pi deployment, camera capture from BEEP, motor command, or live speaker playback was part of this change. The existing bridge still owns LiDAR collision safety, SLAM validity, and mission leases.

## Privacy boundary

- `beep_eyes.privacy.inspect_frame()` fully decodes each raw JPEG *locally*, crops the vendor's top-edge FPS overlay and downsamples the remainder to measure luminance mean and standard deviation. Dark/low-variance frames (mean `<24`, stddev `<14`) and flat bright covers (mean `>235`, stddev `<8`) become `camera_occluded`. Undecodable/truncated frames fail closed too. A dark room and a lens cap are deliberately not distinguished.
- The moving-vision runner checks **every raw JPEG selected for a contact sheet** and the newest ring sample before any Gemini call. The Gemini client independently checks the latest raw JPEG before encoding either image or invoking transport. The opt-in stationary social-view helper screens its raw JPEG before calling its injected captioner.
- On detection, the moving runner emits one local `camera_occluded` trace event with numeric metrics but **no image bytes**, sends a fixed dry English reaction through the direct `/audio/play` sink (host Sonia TTS supplies *text only*, or use `--occlusion-audio-file` with an existing MP3/WAV), and withholds all subsequent image inference. If TTS or playback fails, `audio_confirmed=false` is recorded; no success is invented. The runner waits for a one-way operator switch while independently monitoring the bounded onboard mission. It does **not** issue `/stop`, a gesture, or a mission cancel on mere darkness; exact-owner cleanup at the wrapper's normal deadline remains in force.
- This heuristic cannot recognize *every* possible cap (especially patterned, translucent or illuminated covers). For a **strict corporate no-image-cloud guarantee**, select `--no-cloud-vision` **before launch**, not merely a cap plus detector. A switch cannot recall an API request already in flight. No-cloud **vision** still permits text-only external TTS and, if separately consented, audio/chat services.

## Operator controls

Start a bounded autonomous mission with **no camera capture, vision credentials, or image API requests** by passing `--no-cloud-vision` to `scripts/run_beep_explore.py`; the child `run_moving_eyes.py` only monitors the existing LiDAR/SLAM mission. Pass `--memory-file /home/max/.hermes/profiles/sol/beep_memory_bank.json` if the host-side session should load the seeded trip notes (the wrapper forwards it to its child). All ordinary physical placement, supervision, and bridge readiness gates still apply. Do not run this command merely to test the host code.

For an already-running camera observer, the `camera_occluded` event prints a `vision_switch_file` path (by default `<output-root>/<run-id>/vision_mode`). On the **host**, write the literal line `no-cloud-vision` to that path; equivalently supply `--vision-switch-file /persistent/local/path` at launch and write there. The latch cannot be reversed within a session, even by deleting/replacing the file; restart under an explicit approved privacy mode for any future cloud use. While the operator has not switched, the observer waits without another Gemini request. A mission may finish in the meantime.

`run_beep_life_loop.py --no-cloud-vision` is accepted for its shadow replay and its **explicit one-shot** `--supervised-wave` path. Neither path had an image provider to begin with. `run_social_voice.py --no-cloud-vision` suppresses `--visual-context`; its existing `--speak --bridge-url ...` path can deliver an operator/Telegram-supplied greeting via `/audio/play` after stationary/consent checks. The separate `upward_social_turn(..., no_cloud_vision=True)` refuses visual sitting/capture and suggests direct audio instead. No automatic gesture or operator-trigger router was commissioned by this flag: wave_hand is still the existing one-shot, physical-confirmation-gated tool at a verified stationary boundary, **never during an active patrol lease**.
